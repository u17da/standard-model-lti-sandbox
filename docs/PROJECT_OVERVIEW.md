# プロジェクト概要：相互運用性標準モデル LTI接続テストシステムについて

本ドキュメントでは、本プロジェクト（LTI接続テストシステム）が開発された背景、目的、およびその社会的意義について詳細に解説します。

---

## 1. 背景：GIGAスクール構想と教育データの標準化

### 1-1. 新たなデジタル学習環境の構築
文部科学省が推進する「GIGAスクール構想」により、児童生徒1人1台端末の環境はほぼ整備されました。次のフェーズとして、様々な学習ツールを活用し、そこから得られた教育データ（スタディ・ログ）を効果的に連携・活用することで、子供たち一人ひとりに最適化された学びを実現することが求められています。

### 1-2. 標準化の必要性
多様な学習ツール（デジタル教科書、ドリル教材、動画教材など）が学校現場で活用される中で、それぞれのツールが独自の接続方式を採用してしまうと、以下の問題が発生します。

*   **学校・自治体**: アカウント管理が煩雑になり、シングルサインオン（SSO）が機能しない。
*   **ツール事業者**: eポータルごとに個別の接続開発が必要となり、開発・維持コストが増大する（「車輪の再発明」）。
*   **データ連携**: データの形式がバラバラで、横断的な分析が困難になる。

これらの課題を解決するために策定されたのが、**「初等中等教育におけるシステム間連携のための相互運用標準モデル」**（以下、標準モデル）です。

---

## 2. 本テストシステムの目的

本システムは、学習eポータル標準モデル（Ver. 5.00）に準拠したLTI 1.3接続（ツール起動・SSO）の動作検証を行うための、**開発者向けリファレンス実装（サンドボックス）**です。

### 2-1. 「ニワトリ・タマゴ問題」の解消
新しい標準仕様が普及する過程では、「対応したプラットフォームがないからツールが作れない」「対応したツールがないからプラットフォームが作れない」というジレンマが発生します。
本システムは、**「誰でも・無償で・すぐに使える標準準拠のプラットフォーム」** を提供することで、ツール事業者が先行して「標準モデル準拠ツール」を開発・検証できる環境を提供します。

### 2-2. 日本固有仕様（Japan Profile）の正確な実装支援
LTI 1.3は国際標準規格ですが、日本の初等中等教育においては独自の運用ルール（プロファイル）が存在します。
*   **学年情報の連携**: `https://purl.imsglobal.org/spec/lti/claim/custom` を用いた学年データの受け渡し。
*   **役割（Roles）のマッピング**: 教員、児童生徒のロールIDの厳密な定義。
*   **プライバシー配慮**: `prompt=none`（サイレントログイン）の必須化。

本システムでは、これらの日本固有ルールを厳密にシミュレートすることで、実際の学校現場でトラブルなく動作するツールの開発を支援します。

### 2-3. 「Zero Burden（負担ゼロ）」検証の実現
ツール事業者が各社のeポータル（まなびポケット、OpenPlatformなど）と個別に契約・接続検証を行うコストは甚大です。
本システムは、以下の特長により検証コストを極小化します。
*   **即時利用可能**: 面倒な利用申請や契約手続き不要。
*   **意図的なエラー生成機能**: 不正なリクエストに対するツールの堅牢性をテスト可能。
*   **相互運用性証明書の発行**: 接続成功の証跡をデジタル証明書として発行し、品質保証の一助とする。

## 3. 本システムの社会的意義

### 3-1. 教育DXエコシステムの健全な発展
開発障壁を下げることで、ベンチャー企業や中小の教材会社でも「標準準拠のデジタル教材」を開発しやすくなります。これにより、多様で質の高い教材が市場に供給されるエコシステムの発展に寄与します。

### 3-2. 学校現場の混乱防止
「規格には準拠しているはずだが、特定の条件下で動かない」といったトラブルを未然に防ぎます。事前に本システムで十分なエッジケース（エラー系テスト）を行っておくことで、学校現場導入時のトラブルシューティングコストを削減します。

### 3-3. オープンな知見の共有
本システム自体がオープンな実装例として機能するため、プラットフォーム開発者・ツール開発者双方が「標準仕様をコードレベルでどう解釈すべきか」という知見を共有するハブとなります。
